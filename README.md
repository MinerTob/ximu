# 云端聊天室

一个基于数据库的网页多人聊天应用：注册登录、实时在线状态、一对一私聊，支持发送图片和视频。消息在服务器加密存储，任何设备登录都能查看历史，微信式使用体验。

主要亮点：**邮箱验证码注册**、**二维码登录**、**自动翻译 Bot**、**未读 / 已读回执**、**撤回与转发**、**服务器加密**、**QQ 群式管理后台**（站主 / 管理员 / 禁言 / 封号 / 举报 / 邮件箱）、三语言界面与移动端适配。

## 功能

- 注册 / 登录（密码加盐哈希存储，登录状态持久化，一台电脑可多开多个账号）
- **注册邮箱动态验证码**：注册时需先获取 6 位邮箱验证码并验证通过（防止恶意注册刷号）
- **二维码登录**：登录页可生成随机二维码（10 分钟失效），在个人资料点击扫码图标扫描即可快速登录
- 每个新用户自动分配 10 位数字 ID 和乱码「邀请码」身份
- 实时在线状态：绿色圆点表示该用户当前已连接服务器
- 在线 / 离线用户均可选择聊天，离线用户上线后可看到消息
- 电脑端对话可**点一下打开、再点一下收起**（微信电脑版手感）：点同一个用户第二次，聊天区回到「选择一个用户开始聊天」的初始界面
- 发送文本消息（Enter 发送，Shift+Enter 换行）
- **自动翻译 Bot**：中文（简/繁）消息自动翻译成英语，英文消息自动翻译成简体中文，结果显示在消息下方
- 上传图片和视频（最大 150MB），聊天中直接预览
- 点击聊天中的图片会**全屏放大查看**（页面内灯箱，点任意处关闭），手机端不再依赖弹新窗口
- **微信式服务器加密**：文本消息加密后存入数据库，图片/视频加密后落盘，外人拿到数据库文件或上传目录也读不出内容
- 历史消息自动保存，登录任意设备/浏览器都能查看（无需任何设备钥匙，和微信一致）
- **未读 / 已读**：未读数计入服务端（离线期间收到的消息登录后也亮红点），打开对话即标记已读；自己发出的消息下方显示抖音式「未读 / 已读」小字，对方打开对话后实时变为「已读」
- 消息搜索（可按用户名 / 数字 ID / 邀请码）
- 微信式**撤回消息**：手机长按 1 秒、电脑端**右键**即可弹出菜单撤回（2 分钟内）；撤回时**内容物理抹除**（图片/视频文件直接从磁盘删除，不占空间），只保留一个几字节的撤回标记——双方刷新页面后仍能看到「撤回了一条消息」
- **转发消息**：手机长按 1 秒 / 电脑端右键消息 → 选「转发」→ 选择用户；转发后与普通消息完全一样，只是底部显示「转发自 原发送者」；文字直接复制内容，图片/视频会复制一份独立文件，不影响原消息
- 个人资料：修改用户名、简介、头像（表情或上传图片）；点击头像查看自己资料 / 对方个人主页
- 管理后台（QQ 群式权限）：站主 / 管理员（OP）可查看聊天记录、发警告、删消息，并可实时授予或取消其他用户管理员权限
- 禁言 / 封号、批量注销（防止恶意注册刷号）
- 举报与邮件箱（管理员邮箱分为「检举信处理 / 通知邮件」两栏）
- 弹窗层级：所有弹窗按打开先后自动置顶，最新打开的永远在最上层
- 三语言界面：简体中文 / 繁體中文 / English（美式）下拉切换，选择后自动记住
- 移动端适配：iPhone / iPad / 安卓自动切换为「全屏列表 + 全屏对话」的抽屉式界面，并适配刘海屏 / 底部安全区

## 技术栈

- 后端：Node.js + Express + Socket.IO
- 数据库：SQLite（better-sqlite3），数据保存在 `data/chat.db`
- 文件上传：Multer，文件保存在 `uploads/` 目录
- 二维码：qrcode（生成）+ jsqr（浏览器端扫码识别）
- 前端：原生 HTML / CSS / JavaScript（无需构建）

## 启动方法

```bash
npm install
npm start
```

然后打开浏览器访问 <http://localhost:3000>。

**推荐用 `start.bat` 启动**（已内置邮箱验证码等环境变量）：直接双击 `start.bat` 即可，无需手动设置环境变量；如用 `npm start` 请先自行配置邮箱相关变量。

如果手机或其他电脑想一起聊天，需要电脑和它们在同一网络（同一 WiFi/局域网），然后访问 `http://<电脑的局域网IP>:3000`。服务器启动时会自动打印当前的局域网访问地址（例如 `局域网访问（手机/平板等同一 WiFi 设备）：http://192.168.4.37:3000`），也可以自己用 `ipconfig` 查看 WLAN 的 IPv4 地址。

如果其他设备打不开，通常是 Windows 防火墙拦截：首次启动 Node.js 时弹出的防火墙提示选「允许访问」，或在「Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙」中把 Node.js 的专用网络勾上。

## 关闭服务器

服务器是在你启动它的那个命令行窗口里运行的。关闭方法：

1. 切回运行 `npm start` 的那个命令行窗口；
2. 按 `Ctrl + C`；
3. 看到提示后，通常再按一次 `Ctrl + C`（或输入 `y` 回车）即可彻底退出。

关闭后，浏览器里将无法再访问聊天页面。数据不会丢失，下次运行 `npm start` 后历史消息和账号都还在。

## 消息加密（微信式服务器加密）

- 文本消息在写入数据库前用服务器的密钥（AES-256-GCM）加密，数据库文件里的内容是不可读的密文；图片和视频在服务器上加密落盘，只有登录用户才能解密查看；
- 登录任意设备/浏览器都能查看全部历史消息（图片/视频同样可看），无需任何设备钥匙，和微信一致；
- 加密密钥在首次启动时自动生成，保存在 `data/secret.key`。**请务必保留这个文件**：一旦丢失，之前的所有聊天记录都将无法解密；
- **传输安全依赖 HTTPS**：浏览器与服务器之间通过 HTTPS（TLS）传输，外人抓包只能看到密文。请务必使用 https 隧道（如 ngrok / cpolar 的免费 https 域名），不要用明文 http 隧道；
- 服务器（站主/管理员）能解密查看聊天内容，这是服务器加密模式的固有属性；站主/管理员在管理后台可直接查看聊天记录原文；
- 老版本（v3.9 及更早）的端到端加密历史消息在数据库中仍是旧格式密文，服务器无法解开，会显示「（端到端加密消息，内容不可见）」；这类历史消息只能删除。

## 未读 / 已读

- 未读数存在服务器数据库里：用户离线时收到的消息也会累计，登录后左侧用户列表对应的人头像右上角亮起红色角标（带数量，仿邮箱）；
- 打开和对方的对话即标记已读，红点消失、计数清零；
- 自己发出的每条消息（文字、图片、视频）下方显示抖音式「未读 / 已读」小字：对方没看时是灰色「未读」，对方打开对话后实时变成蓝色「已读」；对方正开着对话时收到你的消息，也会立即标记已读；
- 升级前的老消息默认视为已读，不会一上来满屏红点。

## 自动翻译 Bot

- 规则：消息包含中文（简体/繁体都算）→ 自动翻译成**英语**；纯英文消息 → 自动翻译成**简体中文**；其他语言/表情不翻译；
- 翻译结果显示在每条文字消息的下方（微信风格：白色小方框挂在气泡下面），原文保留不变；
- 翻译结果会缓存（内存 + 数据库），同一句话只调用一次翻译服务；前端每个浏览器也会缓存，翻历史不重复请求；
- **谷歌翻译（生产部署默认）**：优先走谷歌 **Chrome 扩展接口**（`clients5.google.com`，机房 IP 下比常规接口更不易被 429 限流），再走常规接口兜底；两条都被限流时才切 MyMemory 备用源（带邮箱参数走独立每日额度，默认复用 `MAIL_FROM`，可用 `TRANSLATE_MYMEMORY_EMAIL` 单独指定）；全都不通则不显示翻译（不影响聊天）；
- 可用环境变量更换翻译服务：
  - `TRANSLATE_URL`：Google 接口地址（默认 `https://translate.googleapis.com/translate_a/single`，需要返回 Google 格式的 JSON）；
  - `TRANSLATE_DISABLED=1`：关闭自动翻译；
- **隐私说明**：需要翻译的消息文本会发送给 Google（或兜底 MyMemory）。如果介意，请关闭自动翻译。

## 邮箱动态验证码

- 注册流程：填邮箱 → 点「获取验证码」→ 输入 6 位数字验证码 → 提交注册；验证码 10 分钟内有效、只能用一次、60 秒内不能重复发送；
- 一个邮箱只能注册一个账号；已有账号的邮箱不能再次使用；
- **配置**：
  - `EMAIL_VERIFY`：默认开启（`1`），设为 `0` 可临时关闭邮箱验证（老数据不受影响，只是新注册不再强制）；
  - `MAIL_PROVIDER`：`console`（默认）/ `resend` / `brevo`；
  - **通解说明**：发信端统一走第三方邮件发送服务（API），**收件人不管是 Gmail、QQ、163 还是 Outlook，都能收到**，不需要针对每个邮箱单独配置。默认 `console` 模式不真发信（验证码只打印在服务器控制台并存入数据库，适合本地调试）——之前 Gmail 收不到就是这个原因；
  - **Resend**（`MAIL_PROVIDER=resend`）：注册 resend.com → 拿到 API Key → 设置 `RESEND_API_KEY` 和 `MAIL_FROM`；要发给任意收件人需在 Resend 里验证一个发件域名；
  - **Brevo / Sendinblue**（`MAIL_PROVIDER=brevo`）：注册 brevo.com → 验证一个发件邮箱（不需要域名）→ 设置 `BREVO_API_KEY` 和 `MAIL_FROM`，即可发给任意邮箱（免费额度每天 300 封）；
  - 正式部署时二选一配置即可；`console` 模式适合开发测试，不会真发邮件。

## 二维码登录

- 登录页点「使用二维码登录」会生成一个**随机二维码**，10 分钟后自动失效（可点「刷新二维码」重新生成）；
- 已登录账号：点左上角头像进入个人资料 → 点头像右侧的**扫码图标** → 对准屏幕上的二维码（或选择图片识别）→ 确认后，登录页自动进入聊天；
- 二维码内容是一个绑定 token 的链接，**只有析木聊天室自己的扫码能完成登录**；用微信等其它扫码器扫了会打开一个「请使用析木聊天室登录」的误扫提示页；
- 电脑端没有摄像头时可点「选择图片识别」，上传二维码截图即可；
- 扫码需要摄像头权限（HTTPS 或 localhost 下可用）。

## 用户身份与一台电脑多开

- 每个注册用户除了用户名，还会自动获得一个 10 位数字 ID（如 `7446378528`）和一个乱码「邀请码」（如 `qnc4-ybmd-s97g`），在左侧头像下方和聊天窗口顶部都能看到，也可用于搜索；
- 一台电脑可以同时开多个账号：每个标签页 / 浏览器窗口各自登录一个账号即可互发消息（登录时把「记住登录状态」取消勾选，多开更省心；也可以直接用隐身窗口）；
- 登录状态默认跟随标签页保存：关掉该标签页后需要重新登录；勾选「记住登录状态」则本机记住账号，下次打开免登录。

## 管理后台（OP）

权限采用 QQ 群式模型，不需要任何配置文件或环境变量：

- 第一个注册的用户自动成为「站主」；之后注册的用户都是普通用户；
- 站主和管理员（OP）的左侧会出现「管理」按钮，点击进入管理后台；
- 在管理后台点开某个用户，右上角有「设为管理员 / 取消管理员」按钮：站主和管理员都可以给其他用户授权或取消授权，实时生效，无需重启服务器；
- 站主的权限不可被修改；
- 用户名后面会自动带上角色后缀：站主显示「（站主）」，管理员显示「（OP）」，在用户列表、聊天窗口和消息气泡里都会显示；
- 管理后台的用户列表和对话消息行都会显示用户自定义头像（上传的图片或表情头像）；
- 管理后台可查看每个用户的聊天记录原文（服务器自动解密），图片/视频直接内嵌预览；只有该用户自己发送的消息会出现「警告」勾选，收到的消息只能删除；删除消息会连同数据库和磁盘加密文件一起**物理清除**，双方聊天界面实时刷新；
- 管理后台每次打开都先显示用户列表，点用户进入对话详情，返回按钮回到列表；消息的「警告 / 删除」操作在电脑端和手机端都**常显**，**点击整条消息即可勾选警告**（电脑端和手机端通用）；点「警告选中」会自动展开原因填写框并聚焦；违规警告面板**高度自适应**（无警告时不撑开空隙，警告多时内部滚动）；头部统计信息（ID / 消息 / 警告）保持单行不遮挡聊天记录；
- 移动端适配：图片/视频在手机上自动缩放到屏宽内不溢出，长文字自动换行；警告原因输入框和聊天输入框在手机上字号保持 16px，聚焦时页面不会被自动放大；
- 「违规警告」面板默认折叠成小标题栏（带倒三角 ▸），点击展开可查看警告记录并删除，删除后对方界面实时同步移除；
- OP 拥有查看全部聊天内容的权限，这是服务器密钥解密的设计，请仅用于站点管理与违规处理，并妥善保管管理员账号密码。

## 禁言 / 封号

- 站主可以禁言/封号任何用户；管理员也可以，但**不能处理站主**；
- 在管理后台点开某个用户，右上角「禁言」按钮弹出「账号处理」窗口，两个选项：
  - **🔇 禁言**：自定义时长（分钟，可直接键盘输入编辑，也有 5分钟 / 30分钟 / 1小时 / 1天 快捷按钮），可填原因；原因也可直接点预设分类（色情低俗 / 涉政敏感 / 侵犯权益 / 诈骗骚扰 / 其他，选「其他」才弹出输入框）；
  - **⛔ 封号**：**永久封禁（保留账号）**，该账号无法登录；被封账号登录时会弹出固定格式封号通知（含封禁时间，如 `2026.08.10.22:56(UTC+8)-∞`、原因、执行管理员）；只能手动解封；
- 被禁言的用户会立刻看到禁言横幅（含解禁时间），输入框和发送按钮自动禁用；临时禁言到期后**自动解封**；
- 禁言横幅显示的是 **UTC+8 时间且精确到秒**（如 `2026-08-09 20:52:14（UTC+8）`），刷新页面后依然正常显示；
- 需要提前解封时，管理后台该用户的按钮会变成「🔇 解封 / ⛔ 解封」，点击即可手动解除；
- 用户列表里被禁言的人显示 🔇，被封禁的人显示 ⛔，聊天窗口顶部也会显示对应状态；
- 站主 / 管理员**查看自己**时不会出现「禁言」「封号」按钮，也不会看到对自己消息的警告勾选；服务器端也会拒绝对自己禁言、警告或封号。

## 个人资料

- 点击左侧自己的头像（或名字），进入个人资料页面；
- 可以修改**用户名**（2-20 位中文/字母/数字，改完后所有地方同步显示，旧用户名立即失效）、**个人简介**（最多 200 字）；
- **头像**支持两种方式：从内置表情里选一个，或上传一张本地图片（最大 5MB）；
- 修改后点「保存」立即生效，其他用户看到的是新名字和新头像（用户列表、聊天消息、管理后台都会同步）。

## 撤回消息与对方主页

- **手机长按自己发送的消息 1 秒**（电脑端直接**右键**），会弹出菜单，点「撤回消息」即可撤回（图片/视频/文字都可以）；对方会实时看到「对方撤回了一条消息」，你这边显示「你撤回了一条消息」；
- 超过 2 分钟无法撤回，这是微信同款规则；
- 聊天窗口顶部显示对方的头像和名字，**点击头像或名字**会打开对方的个人主页：能看到对方的头像、用户名、数字 ID、邀请码、角色、在线状态和个人简介；
- 聊天消息里**点击自己的头像**会打开自己的资料页（可编辑），点击对方的头像会打开对方的个人主页。

## 举报与邮件箱

- 管理员可以直接查看聊天记录，同时保留**用户主动举报**通道：
  - 聊天窗口顶部有「⚠ 检举」按钮，**开关式**：点一下进入勾选模式（每条对方消息出现勾选框），再点一下退出；可勾选一条或多条；
  - 勾选后点「检举选中」，补充说明为预设分类按钮（色情低俗 / 涉政敏感 / 侵犯权益 / 诈骗骚扰 / 其他，选「其他」才弹出输入框；选项为纯文字圆角按钮，无圆圈）；被勾选的消息内容会作为**举报人提交的证据**一并送达管理员；
  - 被举报人会收到一条**匿名服务器通知**（不泄露举报人身份与具体内容）；
  - 站主/管理员右上角邮箱图标（✉）：收到举报信或系统通知时出现红点，多封未读显示数字；点开邮箱后左侧分为「**检举信处理 / 通知邮件**」两栏，右侧查看内容（Gmail 式双栏）；
  - 检举信支持**快捷处罚**：🔇 禁言 / ⛔ 封号（会自动移除被举报的内容，被处罚人收到服务器格式处罚通告——含「我们已移除相关违规内容，并对您的账号进行处罚」，举报人收到答复邮件）、**未发现违规**（只回复举报人，不移除内容）；处理时还可选择反馈类别（色情低俗 / 涉政敏感 / 侵犯权益 / 诈骗骚扰 / 其他）自动套用标准回复模板；
  - 处理过的举报会标记「已处理」（全局状态），不会再重复处理；
  - 管理员和普通用户都可以主动删除邮件（删除不影响举报记录与最终处罚）；
- **封号（注销）记录**也会作为系统通知进入站主/管理员的邮件箱，便于审计。

## 磁盘清理（物理删除）

- 管理员删除消息、举报处罚移除内容、批量注销账号，都会把对应的数据库记录和磁盘上的图片/视频文件**直接物理删除**（不是移到回收站）；用户撤回消息会**抹除内容并删除媒体文件**，只留一个几字节的撤回标记，双方刷新后仍显示「撤回了一条消息」；
- 服务器启动时和每小时会自动扫描上传目录，清理「数据库里已无任何消息/头像引用」的孤儿文件（最近 10 分钟内刚上传的文件会先跳过，避免误删）；
- 如需手动触发，站主/管理员可调用清理接口（`POST /api/op/cleanup-files`，例如用 API 工具请求一次），不依赖自动定时清理。

## 多语言

- 登录页和聊天侧边栏都有**下拉选择器**切换语言：简体中文 → 繁體中文 → English（美式），选择后自动记住；
- 界面文案（登录、聊天、管理后台、邮件箱、举报等）随语言切换；服务器返回的常见错误提示也做了翻译。

## 批量删除（防止恶意注册）

- 除了邮箱验证码外，管理后台还提供批量处理能力，进一步防止恶意注册刷号；
- 管理后台用户列表每行有一个勾选框（自己的那行没有），勾选多个用户后底部出现「批量删除」；
- 点击后二次确认，选中的账号及其聊天记录、警告记录会被**彻底删除**，对方被强制下线（与「封号」不同：封号保留账号，批量删除是彻底清除恶意注册账号）；
- 批量操作会自动跳过站主和自己，并提示每个被跳过的原因。

## 移动端使用（iPhone / iPad / 安卓）

- 打开网页后默认显示全屏用户列表，点一个用户进入全屏聊天，左上角 ‹ 返回用户列表；
- 管理后台同理：默认全屏用户列表，点用户进入全屏详情，左上角 ‹ 返回；
- 已适配刘海屏 / 底部横条的安全区，按钮位置不会被遮挡；
- 建议把网页「添加到主屏幕」，体验更接近原生 App。

## 账号与数据持久化

- 所有用户账号、聊天记录、警告记录都保存在 `data/chat.db` 数据库文件中，关闭服务器、重启电脑都不会丢失，**重启后直接用原账号登录即可，不需要重新注册**；
- 服务器支持优雅关闭：按 `Ctrl + C` 时会先保存数据再退出，请优先用这种方式停止，而不是强制结束进程；
- 除非你主动删除 `data/` 目录，否则数据会一直保留。

如果想换一个端口启动（例如同时运行多个实例），可以使用：

```bash
set PORT=3001
npm start
```

## 安全说明

- 密码使用 scrypt 加盐哈希存储；消息和文件使用 AES-256-GCM 加密落盘；上传文件按 MIME 类型校验；消息内容有长度限制；
- 当前采用**微信式服务器加密**：消息由服务器密钥加密存储，站主/管理员可解密查看（管理后台可见原文）；传输安全依赖 HTTPS，请务必使用 https 隧道访问，不要用明文 http；
- 若部署到公网，仍建议加 HTTPS、登录限流（例如注册频率限制）、消息审核和更严格的文件安全策略。
